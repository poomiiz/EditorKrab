# ระบบทีม EditorKrab

## ตั้งค่าบัญชีกลาง

ใช้ Supabase โครงการเดิม เปิดยืนยันอีเมล และติดตั้ง migrations ตามลำดับใน `supabase/migrations/` ผ่านผู้ดูแลฐานข้อมูล แล้วตั้งค่า `supabase_url` กับ `supabase_anon_key` ใน config ของชุดติดตั้งโดยผู้ดูแล EditorKrab ผู้ใช้ทั่วไปไม่ต้องกรอกค่าเชื่อมต่อเอง ห้ามใส่ service role key

ผู้ใช้สมัครเอง ผู้สร้างองค์กรเป็น `admin` ผู้ดูแลเพิ่มสมาชิกที่สมัครและยืนยันอีเมลแล้วเป็น `lead` หรือ `editor` หนึ่งบัญชีอยู่หนึ่งองค์กร สมาชิกเดิมและแพ็ก preset ถูกผูกกับองค์กรเดิมโดย migration โดยไม่สร้างบัญชีใหม่ หากข้อมูลสมาชิกเดิมกำกวมหรืออยู่หลายองค์กร migration จะหยุดให้ผู้ดูแลแก้ข้อมูลก่อน

## ไฟล์ทีม

องค์กรเลือก Syncthing หรือ Google Drive for desktop และแชร์โฟลเดอร์ให้สมาชิกด้วยเครื่องมือนั้น ใน **ทีม → ตั้งค่าโฟลเดอร์ทีมในเครื่องนี้** เลือกเครื่องมือและโฟลเดอร์ที่มีอยู่แล้ว ตั้งค่าเครื่องมือให้ซิงก์เฉพาะ `footage/` กับ `exports/` ห้ามซิงก์โฟลเดอร์โปรเจกต์ CapCut/HyperFrames หรือโฟลเดอร์ติดตั้ง EditorKrab

EditorKrab ตรวจว่าโฟลเดอร์มีอยู่และเขียนได้ ฟุตอ้างอิงชื่อไฟล์กับขนาดที่แน่นอนในองค์กร ไม่ใช้ path บนเครื่องเป็น ID ฟุตที่ยังมาไม่ครบแสดง “ยังไม่ได้ sync” สถานะ เจ้าของ และประวัติอยู่ใน Supabase เท่านั้น

## รับงานและตรวจงาน

1. วางฟุตใน `footage/` เมื่อไฟล์พร้อมแล้วเลือกเพิ่มฟุต และเพิ่มเรื่องบรรทัดละหนึ่งเรื่อง รายการใหม่ยังไม่มีเจ้าของ
2. คนตัดกด **รับงาน** ฐานข้อมูลเปลี่ยนเจ้าของเฉพาะงานที่ยังว่าง ป้องกันรับซ้ำ เจ้าของผูกโปรเจกต์ส่วนตัวในเครื่องแล้วเปิดแก้
3. ส่งออก MP4 ลง `exports/` แล้วเลือก **ส่ง MP4 ตรวจ** → **👀 รอลูกค้าตรวจ** คนตัดเปลี่ยนผลตรวจไม่ได้
4. หัวหน้าเปิดหน้าตรวจงาน ตรวจ MP4 แล้วเลือกหลายงานเพื่อ **🔁 ต้องแก้** หรือ **✅ อนุมัติแล้ว** พร้อมบันทึกคำตอบลูกค้า งานอนุมัติถูกล็อกและเก็บคนอนุมัติกับเวลา
5. งานต้องแก้กลับเป็น **✂️ กำลังทำ** เมื่อเจ้าของเปิดแก้ หัวหน้าปลดล็อกหลังอนุมัติหรือโอนงานได้โดยระบุเหตุผล ประวัติเก็บเจ้าของเดิม เจ้าของใหม่ ผู้โอน และเวลา

หน้าโปรเจกต์กรองงานของฉัน/ยังไม่มีคนรับได้ หน้าหัวหน้ากรองงานรอตรวจ/อนุมัติ/ทุกงาน การส่งหลายงานใช้ MP4 ที่ผูกไว้แล้ว แต่ละงานต้องเป็นของผู้ส่งและอยู่ในสถานะส่งตรวจได้ รายการทั้งหมดล้มเหลวพร้อมกันหากงานใดเปลี่ยนไปแล้ว

## ข้อจำกัดและหลักฐานที่ยังต้องตรวจ

- โอนงานแล้วเจ้าของเดิมส่งโปรเจกต์ให้เจ้าของใหม่โดยตรง ไม่วางในโฟลเดอร์ซิงก์ทีม ไฟล์ตรวจงานเป็น MP4 ตามที่ผู้ใช้ยืนยัน วิธีส่งโปรเจกต์ข้ามเจ้าของยังต้องกำหนดก่อนใช้งานโอนจริง
- API ของ EditorKrab ตรวจเจ้าของและสถานะก่อนเข้าถึงโปรเจกต์ที่ผูกกับทีม แต่ไม่สามารถห้าม CapCut เปิดสำเนาเก่าที่ค้างบนเครื่องเจ้าของเดิม ต้องจัดการสำเนาและสิทธิ์บนเครื่องนั้นก่อนรับรองการล็อกไฟล์โดยตรง
- การยืนยันสถานะเดิม 56 งานยังอยู่ในข้อมูลประวัติบนเครื่อง ไม่มีการสร้างเจ้าของหรือยืนยัน MP4 บน Supabase โดยเดา
- ยังไม่ตรวจการสมัครจริง/ฐานข้อมูล Supabase ที่ติดตั้งจริง/การซิงก์จริงจากสองเครื่อง ทั้ง Syncthing และ Drive for desktop รวมถึงไฟล์ online-only ความเร็วเน็ตและพื้นที่เก็บไฟล์
- ตรวจในเครื่องด้วย SQL `supabase/tests/owner_workspace_test.sql` บน PostgreSQL แยกจากระบบจริง การทดสอบ SQL ครอบคลุมสิทธิ์องค์กร เจ้าของ รับงานซ้ำ หัวหน้า และ rollback หลายงาน
- ตรวจ migration ทั้งกรณีทีมเดิมว่างและมีสมาชิก/preset เดิมแล้ว ภาพหน้าจอ UI ใช้ข้อมูลจำลอง ไม่ใช่หลักฐานการซิงก์จริง

## ชื่อเรื่องและข้อมูลข้ามเครื่อง

เจ้าของเปลี่ยนชื่อเรื่องจากหน้าทีม ข้อมูลชื่ออยู่ใน Supabase โฟลเดอร์โปรเจกต์ส่วนตัวใช้ชื่อเดิมเพื่อรักษาการผูกสิทธิ์ หน้าทีมอ่านสถานะล่าสุดทุก 15 วินาทีขณะว่าง โดยไม่ทับแบบฟอร์ม การเลือกโอนงาน หรือไฟล์ที่กำลังเลือกอยู่

หน้าแรกอ่านสถานะจาก Supabase สำหรับโปรเจกต์ที่ผูกกับทีม สถานะเก่าของงานที่ยังไม่ผูกถูกระบุเป็นประวัติ หากยังไม่เข้าสู่ระบบหรือผู้ให้บริการขัดข้องจะแสดงเหตุผลแทนการใช้สถานะเก่าแทน หน้าตรวจงานตรวจสิทธิ์ admin/lead ที่เซิร์ฟเวอร์ก่อนแสดงหน้า ฟุตที่ซิงก์ครบมีปุ่มสร้างโปรเจกต์และการลากไฟล์ค้นหาในโฟลเดอร์ footage ของทีมได้


## Google login: ผู้ดูแลตั้งครั้งเดียว

1. ใช้บัญชี Google ของผู้ดูแลเปิด Google Cloud Console สร้างหรือเลือกโครงการ EditorKrab แล้วเปิด Google Auth Platform
2. ตั้ง Audience สำหรับผู้ใช้ภายนอก และเริ่มด้วยบัญชีทดสอบของผู้ดูแล ระบุเฉพาะ scopes openid, email, profile ไม่ขอสิทธิ์ Drive
3. สร้าง OAuth Client ชนิด Web application ใส่ Authorized redirect URI ที่คัดลอกจาก Supabase → Authentication → Sign In / Providers → Google (เป็น https://<project-ref>.supabase.co/auth/v1/callback)
4. นำ Client ID และ Client Secret ไปใส่ที่ Google provider ใน Supabase แล้วเปิดใช้งาน Secret อยู่ใน Supabase เท่านั้น ไม่ใส่ใน EditorKrab และไม่ส่งในแชต
5. Supabase → Authentication → URL Configuration เพิ่ม Redirect URL สำหรับแอปเครื่องนี้: http://127.0.0.1:8770/api/team/google/callback** ถ้าเปิดแอปผ่าน localhost ให้เพิ่ม http://localhost:8770/api/team/google/callback** ด้วย เครื่องที่ใช้ port อื่นต้องระบุ port นั้นแทน suffix รองรับ state ที่แอปสุ่มในคำขอ
6. ผู้ดูแล EditorKrab ตั้ง supabase_url และ supabase_anon_key ของโครงการเดิมในชุดติดตั้ง และติดตั้ง migrations ตามหัวข้อด้านบน ผู้ใช้ทั่วไปไม่กรอกเอง
7. เปิดแอปจะเจอหน้าเข้าสู่ระบบก่อนใช้งาน กดเข้าสู่ระบบด้วย Google ในเบราว์เซอร์เดิม เมื่อ Google กลับมา EditorKrab จะแลกรหัสด้วย PKCE แล้วสร้าง session บนเครื่องนี้ รหัสคำขอหมดอายุใน 10 นาทีและใช้ซ้ำไม่ได้
8. ก่อนแจกให้ทีม ให้ผู้ดูแลเปลี่ยน Google Audience จาก Testing เป็น Production ตามเงื่อนไข Google และตรวจจริงสองบัญชีว่า editor ไม่ได้สิทธิ์ lead/admin และอ่านองค์กรอื่นไม่ได้

ไม่ต้องใช้ Resend หรือโดเมนส่งอีเมลสำหรับ Google login แอปเข้าสู่ระบบด้วย Google อย่างเดียว ไม่มีบัญชีอีเมลและรหัสผ่าน Google login ไม่ได้ให้สิทธิ์ในองค์กรโดยอัตโนมัติ ผู้สร้างองค์กรใหม่เป็น admin ขององค์กรที่ตัวเองสร้างตามสเปคเดิม

การทดสอบในเครื่องรุ่น Python เคยครอบคลุม PKCE, cookie ผูกเบราว์เซอร์, คำขอจากเว็บอื่น, หมดอายุ, ใช้ซ้ำ, ยกเลิก และไม่ส่ง token ให้หน้าจอ ยังต้องตรวจ Google และ Supabase โครงการจริงก่อนรับรองการเข้าสู่ระบบ

## หน้าเริ่มใช้งาน

ผู้ที่ยังไม่เข้าสู่ระบบเปิดหน้าตัดต่อหรืออ่านไฟล์และ API งานไม่ได้ ระบบพากลับหน้า login แม้เปิดลิงก์หน้าอื่นโดยตรง เมื่อ session หมดอายุต้องเข้าสู่ระบบใหม่ ชุดติดตั้งมี URL และ Publishable key สาธารณะของบริการ EditorKrab แล้ว ผู้ใช้ไม่ต้องตั้ง Supabase เอง ผู้ที่นำไปโฮสต์บริการของตนต้องเปลี่ยนสองค่านี้ก่อนแจกจ่าย

โลโก้และสโลแกนเคลื่อนไหวด้วย CSS opacity/transform ครั้งเดียว 650 ms ไม่มีวิดีโอ Canvas หรือแอนิเมชันวน และปิด motion ตามการตั้งค่าของผู้ใช้

## เชิญสมาชิกก่อนล็อกอินครั้งแรก

ติดตั้ง `20261012000000_member_invitations.sql` ก่อนอัปเดตแอปรุ่นที่ใช้คำเชิญ ผู้ดูแลองค์กรระบุอีเมล Google ของสมาชิกและสิทธิ์ editor/lead ได้แม้ยังไม่มีบัญชี คำเชิญหมดอายุใน 7 วัน ต่ออายุด้วยการเชิญซ้ำ และยกเลิกจากรายการคำเชิญได้ ระบบไม่ส่งอีเมลให้ สมาชิกเปิดแอปและล็อกอินเอง

ถ้ายังไม่มีองค์กรและมีคำเชิญที่ใช้ได้เพียงหนึ่งรายการ ระบบรับเข้าทีมนั้นเมื่อล็อกอินครั้งแรก หากมีหลายรายการต้องเลือกองค์กรก่อน ระบบยืนยันจาก auth.users ของผู้ล็อกอินจริงและ email_confirmed_at ไม่ใช้ชื่อหรืออีเมลที่พิมพ์ในโปรไฟล์ การเข้าทีมยังถูกจำกัดหนึ่งองค์กรต่อคน สมาชิกเดิมและการเพิ่มบัญชีที่ยืนยันแล้วใช้ได้เหมือนเดิม

ก่อนติดตั้งจริง: ทดสอบ `supabase/tests/member_invitations_test.sql` หลัง migrations บน PostgreSQL แยก  วิธีย้อนกลับ: คืนแอปเป็นรุ่นก่อนคำเชิญก่อน แล้วรัน `supabase/tests/member_invitations_rollback.sql` ซึ่งเก็บคำเชิญและสมาชิกที่เข้าทีมแล้วไว้ ไม่ลบข้อมูล

## ลิงก์ Google Drive สำหรับดูบนมือถือ

ปุ่มอัปโหลด Drive ไม่เปิดสิทธิ์สาธารณะ ให้เจ้าของเพิ่มผู้ตรวจที่ต้องการใน Google Drive เอง สมาชิกทีมใน EditorKrab ไม่ได้รับสิทธิ์ Drive อัตโนมัติ ระบบตรวจสิทธิ์โฟลเดอร์และไฟล์ก่อนคืนลิงก์ รวมถึงไฟล์ที่เคยอัปโหลด หากพบการแชร์แบบทุกคน/ทั้งโดเมนหรืออ่านสิทธิ์ไม่ครบ จะหยุดให้ตรวจใน Drive ก่อน ลิงก์สาธารณะเดิมไม่ถูกเพิกถอนอัตโนมัติ

ติดตั้ง `20261012010000_share_links.sql` ก่อนอัปเดตแอปรุ่นที่มีปุ่ม "วางลิงก์ Drive" และ "แชร์ลิงก์ Drive" เจ้าของงานวางลิงก์แชร์ของ Google Drive (`https://drive.google.com/...`) ไว้บนงานได้ หัวหน้าหรือผู้ดูแลแก้ลิงก์ได้ งานที่มีลิงก์แต่ยังไม่มี MP4 ในโฟลเดอร์ทีมส่งตรวจได้ หัวหน้ากด "เปิดลิงก์ Drive" ดูบนมือถือได้ migration นี้เพิ่มคอลัมน์ `share_url` และแก้เงื่อนไขส่งตรวจเพียงข้อเดียว แอปรุ่นเก่ายังใช้ได้ตามเดิม ทดสอบ `supabase/tests/share_links_test.sql` หลัง migrations บน PostgreSQL แยกก่อนติดตั้งจริง
