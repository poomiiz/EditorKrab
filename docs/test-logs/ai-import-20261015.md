# EK-03: revision-bound, recoverable AI import

This checkpoint implements the third package in [the development plan](../implementation-plan-20261015.md).
It is implementation and regression evidence, not human approval of an edited clip.

## Resulting behavior

- Stories and clip packets use schema 2. Copy opaque `packet_id`, `revision` and `source_id` from the packet.
  New answers must match the latest packet and source, transcript, brief, duration, cues, style, preset,
  fonts, motion templates, native timeline copies and relevant code. Filename equality is insufficient.
- A source is content-hashed on first use; later checks reuse that SHA only for the same canonical source
  and matching size, mtime, ctime and inode. Deliberate content replacement while restoring every stat
  field is outside this cache's detection guarantee. Unproven ASR metadata is not trusted as a fresh hash.
- Browser paste, local answer polling and CLI import use the same writer reservation, staging and receipt.
  Exact canonical-answer replay returns the original result, including after response loss or later edits.
  Another answer for that packet is refused. Receipts are bound to the actual target; copying a project
  does not authorize replaying its original receipt. Native/template clones exclude source AI state.
- Cuts, merges, cue migration, metadata, history and timeline copies are prepared privately. Motion assets
  have unique names in transaction-owned storage. A later render failure cannot overwrite an old MOV.
- Before applying, dependencies are checked again. Before the durable receipt, the complete metadata
  and normalized dependency revision are checked, including untouched files. Outside edits are preserved.
- Ordinary failures roll back changed files and newly created directories. After process termination,
  a transaction without a receipt is rolled back before another edit/import/build. A receipt is the commit
  point. Unknown outside changes stop recovery and retain both versions instead of overwriting them.
  Persistent disk errors or an open CapCut can prevent immediate recovery; retain the local journal,
  resolve that condition and retry. This is process-restart evidence, not a power-loss certification.
- Pending answers are archived on successful export; successful local answers retain an imported copy.
  Uploaded instructions contain the adjacent answer basename, not the machine's absolute answer path.
  Legacy v1 story/clip packets remain readable but cannot mutate work; export a fresh packet.
  The independent Browser AI insert-sheet contract remains schema 1.

## Verification

Focused suites cover packet identity (14), transaction/replay/recovery (17), project reservations (10),
unique motion assets (4), independent insert contract (3), native preservation (14) and HF export safety (13).
Transaction cases include failure at each of ten real replacements, second-motion failure after a cut,
actual child-process exit followed by a fresh CLI recovery, concurrent paste/poll, response/archive loss,
receipt-write completion followed by an error, copied state, and external changes during application.
Motion asset unit tests stub the renderer; they do not certify HyperFrames visual output.

The final working-tree sweep passed **47/47 Python test programs** in 216.672 seconds; the focused
run with private configuration reads forbidden passed **48 cases**. Individual outputs are stored
privately in `state/ek03-test-logs/` (`final-summary.json`, `final-clean-config-summary.json`).
Some local suites belong to pre-existing uncommitted installer/library work, so a local sweep is not a
claim that those unrelated files have been published. Final CI must be assessed on its exact commit.
EK-02's clean-machine fixture fix `d97c554` passed [CI run 38698122737](https://github.com/poomiiz/EditorKrab/actions/runs/38698122737).

Playwright used the unmodified `editor.html` and real video API router on an isolated loopback server,
generated eight-second blue footage/sine audio and simulated word clocks. It downloaded a real v2 packet,
rejected a v1 reply, imported a four-second retained timeline, and replayed the same reply through the
visible form. Readback found one receipt and identical project-file hashes after replay. No customer
media, Google sign-in or external AI provider was involved. Private screenshots/readback are retained
in `state/ek03-ui-evidence/`.

Desktop controls passed at 1440×1000. **375×844 remains failed**: existing minimum widths clip controls
and move the editor panel outside the viewport. The isolated harness produces expected missing shell
version/update endpoint 404s, the intentional v1 import 400, and existing player sandbox warnings;
this is not a clean whole-app browser pass.

The legacy Browser AI control now shares one submission lane for paste and polling and ignores responses
from older exports. The Node caller suite verifies that native preparation runs once, even when a saved
answer and pasted answer race, or when refresh fails after a successful import. UI error and stale-response
cases retain typed JSON. Team entry/refresh regressions also passed. Playwright captured the actual legacy
control function and its existing CSS in an isolated component harness at desktop and 375px after this
JavaScript fix; these component screenshots do not establish whole-app responsive acceptance. The added-line
raw-colour check is clean; no customer-facing copy or layout was changed by that fix.

Native CapCut opening/playback, audible subtitle synchronization, semantic story quality, subtitle layout,
motion relevance/collision checks and time until human approval remain later acceptance gates. The overall
EK-01–EK-12 goal stays active; no stability, accuracy or time-saving claim follows from this checkpoint.
